# Obsidian 插件建议

> [!info] 结论先行
> 当前这个项目最适合走“少插件、强结构、可回溯”的路线。先用内置能力和 `obsidian-git` 跑通文档、知识体系和日志闭环，再按实际需要加装少量插件。

## 当前已可用插件

### 社区插件

| 插件 | 状态 | 适配度 | 用途 |
|---|---|---:|---|
| `obsidian-git` | 已安装 | 高 | 把 Obsidian 文档纳入 Git 版本管理，适合阶段文档、日志、软著材料和回滚 |

### 核心插件

| 插件 | 状态 | 适配度 | 用途 |
|---|---|---:|---|
| `Templates` | 已启用 | 高 | 统一项目章程、过程文档、阶段记录、周报模板 |
| `Daily notes` | 已启用 | 高 | 适合家长高频录入记录、阶段性复盘和中断恢复 |
| `Bases` | 已启用 | 高 | 做知识点总表、题目索引、掌握度视图、短板视图 |
| `Properties` | 已启用 | 高 | 统一 frontmatter 字段，支撑知识体系和状态追踪 |
| `Backlinks` | 已启用 | 高 | 把题目、知识点、证据和报告串起来 |
| `Search` / `Global search` | 已启用 | 高 | 快速找知识点、错题、日志、版本记录 |
| `Outline` | 已启用 | 高 | 长文档导航，适合规范、说明、报告页 |
| `Bookmarks` | 已启用 | 中 | 固定项目首页、阶段路线图、常用报表 |
| `File recovery` | 已启用 | 高 | 防止文档丢失，适合高频编辑场景 |
| `Tag pane` | 已启用 | 中 | 给“阶段 / 学科 / 角色 / 状态”做快速分类 |
| `Page preview` | 已启用 | 中 | 快速查看链接内容 |

## 这套项目里最该优先使用的能力

1. `obsidian-git` 作为主版本管理插件。
2. `Templates` + `Properties` 作为文档结构统一工具。
3. `Bases` 作为知识点总表和掌握度视图载体。
4. `Backlinks` + `Search` 作为跨文档追踪工具。
5. `Daily notes` 作为家长录入和学生周复盘的入口。

## 当前不急着装的插件

### 先不装

- 任务类插件：当前还在建模期，先把知识体系和数据模型定稳，再决定是否需要任务插件。
- 过重的知识图谱增强插件：目前价值不如 `Bases` 和标准笔记结构直接。
- 太多 UI 美化插件：当前目标是可用、可恢复、可追溯，不是追求装饰效果。

### 后续按需评估

- `Calendar`：如果后续把周报、复盘和家长录入固定在日历节奏上，可以考虑。
- `Periodic Notes`：如果要把周频复盘做成固定流程，可以评估。
- `Tasks`：如果项目任务要直接沉到 Obsidian 里，再考虑。
- `Dataview`：如果 `Bases` 不够用，再补充结构化查询能力。

## 当前建议

- 维持现状，不要先装一堆插件。
- 优先把 `obsidian-git`、`Templates`、`Bases`、`Properties`、`Daily notes` 用熟。
- 先把知识体系、题目、掌握状态、报告页全部统一到中文展示。
- 具体执行方式见 [[Obsidian工作流规范]]。
