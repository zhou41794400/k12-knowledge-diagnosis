# 阶段路线图

## Phase1：MVP 范围冻结

状态：`已完成`

目标：
- 冻结 V1 范围、角色、约束、运行方式和建模原则。
- 明确哪些内容属于 MVP，哪些延后。

完成标准：
- 有正式的 [[MVP冻结说明]]
- 项目首页可作为恢复入口
- 后续阶段的输入条件清晰
- 启动/规划类过程文档已建

## Phase2：课标与知识体系建设

状态：`进行中`

目标：
- 按 `学科 -> 学段 -> 年级 -> 主题 -> 知识点` 建标准知识树。
- 建立知识点笔记模板和字段约束。

输入：
- [[MVP冻结说明]]

完成标准：
- 至少形成全学科目录框架
- 数学的课标主线和冀教版适配关系有明确落点
- 知识点卡片字段规范已冻结

## Phase3：数据模型与追踪模型

状态：`进行中`

目标：
- 固定 `KnowledgePoint`、`QuestionRecord`、`EvidenceEvent`、`MasteryState`、`AuditEvent`。
- 定义 BKT 与非 BKT 学科的追踪规则。

## Phase4：本地录入与分析链路

状态：`进行中`

目标：
- 打通照片上传与手动录题两条入口。
- 建立 OCR、分类、知识映射、掌握更新、回写和日志链路。

完成标准：
- 有录入渠道规范
- 有 OCR 与切分规范
- 有题目识别与知识映射规范
- 有回写与复核规范
- 有本地链路验证样例
- 有可执行的本地服务骨架，至少能跑通手动录题闭环

## Phase5：家长端与学生端结果视图

状态：`进行中`

目标：
- 家长端能看到短板、趋势和待复核项。
- 学生端能看到低频复盘结果和下一步建议。

完成标准：
- 有可执行的本地结果视图生成器
- 有家长端总览页
- 有至少一个学生周报样例页
- 结果页中文可读且能回溯到日志

## Phase6：工程化、日志与软著材料

状态：`进行中`

目标：
- 建立独立 GitHub 项目。
- 沉淀日志、架构说明、版本说明和软著材料。

完成标准：
- 有软著材料总览与入口
- 有可执行的软著材料生成器
- 有版本说明和日志索引
- 已形成独立 GitHub 项目规划或落地方案

## 文档同步规则

- 每推进一个阶段，必须同步更新对应过程文档。
- 文档未更新，不视为阶段真正完成。
- 生命周期文档入口见 [[文档更新规则]]。

## 阶段切换条件

1. Phase1 -> Phase2：MVP 边界不可再模糊。
2. Phase2 -> Phase3：知识树和字段定义足够稳定。
3. Phase3 -> Phase4：数据对象和状态流转无歧义。
4. Phase4 -> Phase5：至少一条真实录入链路可跑通。
5. Phase5 -> Phase6：结果页能支持真实复盘与演示。

## 阶段协作说明

- Phase2 与 Phase3 当前可并行推进。
- Phase2 继续补知识体系内容，Phase3 负责把这些内容转成统一数据对象和事件规则。
