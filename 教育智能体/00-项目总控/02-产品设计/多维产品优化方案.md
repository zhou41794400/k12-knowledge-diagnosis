# 多维产品优化方案

> [!important] 当前产品主线
> 先将产品收敛为“河北小学二至三年级数学的本地隐私型错题诊断与短板跟踪工具”。先验证家庭周闭环，再扩年级、学科和云端能力。

## 一、产品角度

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 收窄首版用户 | 首批只服务小学二至三年级数学家庭 | 10 个家庭连续使用 4 周 | P0 |
| 固定核心任务 | 将首页收敛为“录入试卷、处理复核、查看周报” | 新用户 3 分钟内找到录入入口 | P0 |
| 周报商品化 | 周报固定输出 1 个结论、3 个短板、5 个复习任务 | 80% 家长能准确复述下周首要任务 | P0 |
| 建立信任解释 | 每个结论显示题目证据、知识点和可信程度 | 所有掌握度均可回溯到题目 | P0 |
| 限制产品承诺 | 对外统一使用“学习记录、复习辅助”，不使用“保证提分” | 所有外显页面通过文案审查 | P0 |
| 分层付费 | 免费层提供手工录题和基础归类；付费层提供 OCR、趋势、周报和导出 | 试点用户能区分两层价值 | P2 |

## 二、家长使用角度

### 理想主流程

1. 选择孩子、学科和年级。
2. 上传一题一图，或手动录入题干。
3. 核对 OCR 题干、标准答案和学生作答。
4. 只处理系统标出的歧义或低置信度记录。
5. 查看本次错因、知识点和复习建议。
6. 每周查看一次周报，确认下周任务。

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 减少首次输入 | 默认记住最近学生、学科和年级 | 单题录入不超过 60 秒 | P0 |
| 集中复核 | 建立待处理列表，支持修正、确认、放弃 | 家长不需使用命令行处理复核 | P0 |
| 批量录入反馈 | 每题显示待识别、待确认、已解析、需复核 | 任意时刻都能看到处理进度 | P1 |
| 报告转任务 | 短板后直接生成可勾选的复习任务 | 周报阅读到任务确认转化率达 60% | P1 |
| 一键删除 | 按题目、试卷或学生删除数据 | 删除后报告、当前状态和导出一致 | P1 |

## 三、学生使用角度

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 减少负面标签 | 不展示全班排名、“差”等固定标签 | 学生页面无羞辱性和决定性表述 | P0 |
| 强化进步反馈 | 展示“本周已完成”和“比上周更稳定” | 学生能说出自己的一项进步 | P1 |
| 限制任务量 | 每周最多 3 个知识点、5 个任务 | 学生使用时长维持在 10 分钟左右 | P1 |
| 年龄适配 | 低年级使用短句、图标和明确操作 | 8 岁学生无说明也能完成查看 | P2 |

## 四、开发与架构角度

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 原子掌握度更新 | 将同一学生、同一知识点的读改写放入 SQLite 单事务 | 并发 100 次证据后计数无丢失 | P0 |
| 数据库迁移 | 增加 `schema_version` 和可重复运行的 migration | 旧版数据可一键升级和回滚 | P0 |
| 复核服务化 | 增加查询、更正、解决、放弃复核任务的应用层 API | 命令行和界面共用同一逻辑 | P0 |
| 输入校验 | 统一校验学生编号、学科、年级、图片类型和大小 | 非法输入无法写入业务库 | P0·已完成 |
| 准确性分层 | 区分 OCR 置信度、映射置信度、答案置信度 | 任一层低于阈值均不写掌握度 | P0 |
| 备份恢复 | 对 SQLite、JSONL、图片和 Obsidian 结果做版本化备份 | 在新目录可完整恢复 | P1·已完成 |
| 可观测性 | 记录复核规模、schema 版本和 outbox 积压 | `health` 可输出核心健康指标 | P1·基础完成 |
| 界面实现 | 先建本地 Web 界面，再考虑云端 | 家长无需命令行完成主流程 | P1 |

## 五、知识内容与模型角度

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 扩展已发布卡 | 按“二年级数学 -> 三年级数学”逐批发布 | 每张卡均有正例、反例和歧义例 | P0 |
| 真实题双标 | 完成 50 道脱敏真实题的独立双人标注 | 一致性、映射准确率和拒识率可计算 | P0 |
| 建立错因体系 | 区分知识缺失、计算失误、审题失误、表达失误 | 报告不再将所有错题等同为知识未掌握 | P1 |
| BKT 校准 | 积累足够真实时序数据后再估计参数 | 未校准前不对外宣称 BKT 精准追踪 | P2 |
| 学科独立建模 | 数学优先规则/BKT，语文英语使用 MIXED，主观学科使用 RULE | 新学科上线前必须有独立证据规则 | P2 |

## 六、数据和指标角度

> [!info] 北极星指标
> 每周成功生成且被家长查看的有效学习诊断报告数。

| 指标 | 计算口径 | 试点目标 |
| --- | --- | --- |
| 录入完成率 | 成功产生题目记录的录入数 / 开始录入数 | >= 85% |
| 唯一映射率 | 无需人工复核的唯一知识点映射数 / 有效题目数 | >= 70% |
| 错误写入率 | 复核后确认为错误的掌握度写入数 / 总写入数 | < 2% |
| 人工复核耗时 | 家长处理一条复核任务的中位时长 | < 30 秒 |
| 周报查看率 | 被查看周报数 / 成功生成周报数 | >= 70% |
| 四周留存 | 第 4 周仍录入或查看的家庭 / 首周家庭 | >= 40% |

## 七、合规与安全角度

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 监护人授权 | 首次创建学生时确认监护关系和处理目的 | 无授权不建立学生档案 | P0 |
| 数据最小化 | 默认使用匿名学生编号，不收集班级、学校和真实姓名 | 完成主流程无需真实身份 | P0 |
| 本地优先 | 图片、题目和报告默认仅存本机 | 断网可完成全部 MVP 流程 | P0 |
| AI 边界 | 明示 AI 为辅助分析，低置信度必须复核 | 所有 AI 结论页都有边界提示 | P0 |
| 可删除与导出 | 家长可导出和删除学生全部数据 | 导出、二次确认删除和其他学生隔离测试通过 | P1·已完成 |

## 八、商业和运营角度

| 优化项 | 具体动作 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| 先试点后定价 | 先做 10 个家庭的付费意愿访谈 | 得到明确付费场景和拒付原因 | P0 |

| 设计付费实验 | 比较一次买断、家庭年费和本地增值包 | 至少 20 个有效价格访谈样本 | P2 |

## 九、分阶段执行计划

### 阶段 A：可试用闭环（2 至 3 周）

- [x] 完成复核任务查询、人工写入、解决和放弃接口。
- [x] 增加数据库 schema 版本和原子掌握度更新。
- [x] 完成家长端本地 Web 主流程，包含图片上传与 OCR 确认。
- [ ] 完成 50 道真实题双标（依赖监护人授权与真实样本）。

退出条件：家长无需命令行完成录入、复核和查看报告。

### 阶段 B：小规模家庭试点（4 周）

- 招募 10 个河北家庭。
- 每周记录主流程成功率、复核耗时和周报查看率。
- 每周只修复前 3 个高频阻塞点。
- 完成家长访谈与付费意愿验证。

退出条件：录入完成率 >= 85%，周报查看率 >= 70%，无严重错误掌握度写入。

### 阶段 C：数学范围扩展（4 至 8 周）

- 扩充二至三年级数学已发布卡。
- 扩建真实题验收集和错因标注。
- 增加趋势、复习任务和备份恢复。
- 在有真实数据后再评估 BKT 参数。

退出条件：数学试点范围的真实题指标达标，且 4 周留存达到目标。

### 阶段 D：商品化准备

- 冻结版本、审查协议、隐私和 AI 边界。
- 完成安装、升级、备份、删除和故障恢复演练。
- 完成软著材料、GitHub 发布和变更日志。
- 小范围验证价格，不直接大规模投放。

## 十、当前不做

- 不同时扩展全学科。
- 不在真实数据不足时宣称 BKT 精准。
- 不开发直播课、题库刷题和排名功能。
- 不默认上传未成年人数据到外部服务。
- 不把 AI 分析当作教师或专业评估的替代。
