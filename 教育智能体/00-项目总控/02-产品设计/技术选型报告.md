# 启智知踪 K12 智能学习诊断系统 V1.0 - 技术选型报告

> 基于技术栈与个人能力评估：React / TypeScript / Python 主栈

## 1. 引言

本报告旨在为"启智知踪 K12 智能学习诊断系统 V1.0"项目确定统一的技术选型方案。项目当前处于"封闭试点验证前期"，核心目标是快速交付面向家长、以微信小程序为主要载体的最小可行产品（MVP）。技术选型需同时兼顾开发效率、团队熟悉度（React / TypeScript 主栈）和设计品质要求。

## 2. 前端框架选型

**核心决策：采用 React 18 + TypeScript + Taro 跨端框架。**

### 为什么选 React + Taro

| 维度 | 选型建议 | 理由 |
| :--- | :--- | :--- |
| **框架** | React 18 + TypeScript | 当前主栈（TS/React），零学习成本，直接进入开发 |
| **跨端方案** | Taro 4 | 微信小程序 + Web H5 一套代码，React 生态下唯一成熟的跨端方案 |
| **状态管理** | Zustand 或 Redux Toolkit | 轻量、TypeScript 友好、React 生态原生集成 |
| **路由** | React Router / Taro 内置路由 | 小程序端用 Taro 路由，Web 端可叠加 React Router |

**备选方案 V 版**（不采用）：Vue 3 + uni-app。该方案在非 React 团队场景下是更优选择，但本项目团队主力栈为 React，切换框架带来的学习成本远超跨端方案之间的小幅差异。

### Taro 跨端能力评估

| 维度 | 评价 |
| :--- | :--- |
| **微信小程序支持** | 成熟，官方持续维护，社区案例丰富 |
| **Web H5 兼容性** | 良好，Taro 4 内置 Webpack/H5 编译，可输出标准 SPA |
| **社区维护** | 京东开源，v4 已稳定，npm 周下载量高 |
| **React 版本** | 支持 React 17/18，hooks 全兼容 |
| **TypeScript** | 一等支持，类型定义完整 |

## 3. UI 组件库选型

**核心决策：采用 HeroUI Pro（React + Tailwind CSS 体系）**

### 为什么推荐 HeroUI Pro

| 维度 | 说明 |
| :--- | :--- |
| **生态** | React 原生，与 Taro + React 完全兼容 |
| **设计品质** | ◉◉◉◉◉ 极高水平——Tailwind CSS 驱动的设计系统，组件开箱即美，减少 UI 改样式工作 |
| **适合设计师** | 你作为资深 UI 设计师，可直接复用 HeroUI 的设计 Token 体系做品牌定制，不需要从头造轮子 |
| **小程序兼容** | Web 端直接用 HeroUI Pro；小程序端可复用设计 Token + 部分逻辑组件，UI 一致性高 |

### 候选方案对比

| 特性 | **HeroUI Pro (推荐)** | Ant Design | Vant (Vue 方案) | TDesign React |
| :--- | :--- | :--- | :--- | :--- |
| **设计品质** | ⭐⭐⭐⭐⭐ 开箱即美 | ⭐⭐⭐⭐ 实用 | ⭐⭐⭐ 基础 | ⭐⭐⭐⭐ 腾讯出品 |
| **React 生态** | ✅ 原生 | ✅ 原生 | ❌ Vue 仅 | ✅ React 版 |
| **小程序兼容** | Web 侧直接使用；小程序复用 Token | 小程序版需额外适配 | N/A | 有小程序版，但版本迭代慢 |
| **定制灵活性** | Tailwind CSS，完全控制 | CSS-in-JS，重写成本高 | 可定制但样式较老 | 中等 |
| **License** | 付费 | MIT 免费 | MIT 免费 | MIT 免费 |
| **适合你的价值** | 减少改 UI 的时间 | 需大量样式覆盖 | 风格偏朴素，需大量 UI 设计投入 | 稳定但不出彩 |

**结论**：HeroUI Pro 的付费成本远低于你花时间重写样式或跟一个不够美的组件库斗争的成本。对于资深 UI 设计师，选择一套品质足够高的设计系统是做项目的第一生产力。

### 小程序端 UI 策略

Taro 的小程序端不能直接使用 HeroUI Pro 的 DOM 组件，建议采用**分层策略**：

| 场景 | 方案 |
| :--- | :--- |
| Web H5（管理后台 / 家长 Web 端） | 直接使用 HeroUI Pro 全量组件 |
| 微信小程序（核心用户触点） | 使用 Taro 原生组件 + 应用 HeroUI 的 **Design Token**（色板、间距、字体、圆角），达到视觉一致性 |
| 共享 | Tailwind CSS 样式系统双端共用 |

这样既充分利用 HeroUI 的设计品质，又保证小程序端性能最优。

## 4. 数据库与存储选型

**核心决策：构建"本地 + 云端"分层存储体系，采用 PostgreSQL（主库）+ Neo4j（知识图谱）的混合存储方案。**

### 本地存储（离线优先）

| 端 | 方案 | 理由 |
| :--- | :--- | :--- |
| 微信小程序 | **SQLite**（WAL 模式） | 存储学生核心知识点状态（BKT 结果向量），性能卓越 |
| Web H5 | **IndexedDB** + Dexie.js 封装 | 完整事务支持，无容量上限 |
| 同步队列 | IndexedDB / localForage | CRDT 计数器设计，防止冲突 |

### 云端主库

**PostgreSQL**（推荐阿里云 RDS）：
- **强一致性**：家长看到的诊断报告必须是实时快照，ACID 事务保障
- **JSONB 支持**：直接存储 BKT 模型参数等半结构化数据
- **成熟生态**：自动备份、容灾、监控全都有

### 知识图谱引擎

**Neo4j** 图数据库：
- 1028 个知识点构成的树状结构，图遍历查询性能远超 SQL 递归 CTE
- 模型直观：知识点→节点，父子关系→边，与业务逻辑完全对齐
- 未来可直接运行 PageRank 等算法，挖掘"高频卡壳知识模块"

## 5. 整体技术架构

**核心决策：四层架构，前端通过 API 网关访问后端微服务，BKT 管线作为独立服务。**（架构层不因前端选型改变）

### 关键技术决策

| 决策 | 方案 | 理由 |
| :--- | :--- | :--- |
| **BKT 对接** | REST API + FastAPI | 同步请求-响应，团队熟悉 REST，收益远超 gRPC 复杂度 |
| **缓存** | Redis 写穿透 | BKT 推理结果缓存，TTL 1 周，仅新诊断记录时失效 |
| **数据写入** | 本地 CRDT → 云端合并 | 离线优先保证——家长在无网环境操作的诊断数据不丢失 |
| **推送** | 微信订阅消息 | 周报推送触达，无需 App 打开即可通知 |

## 6. 部署与 CI/CD

**核心决策：MVP 阶段最小部署方案，阿里云 ECS + RDS + OSS/CDN。**

### 预算估算

| 服务 | 配置 | 月成本 |
| :--- | :--- | :--- |
| ECS (1台) | 2C4G（突发性能实例） | ¥200 - 300 |
| RDS PostgreSQL | 2C4G | ¥200 - 300 |
| Redis | 2G | ¥100 - 200 |
| OSS + CDN | 10G 流量包 | ¥30 - 50 |
| 其他（日志、SSL） | | ¥50 |
| **总计** | | **¥580 - ¥900/月** |

### 部署策略

- **Web H5** → 阿里云 OSS + CDN，自动编译上传
- **微信小程序** → `miniprogram-ci` 自动预览/上传，审核保留人工门禁
- **后端微服务** → Docker Compose 单机部署
- **监控** → Prometheus + Grafana，API 错误率 > 1% 或 BKT 延迟 > 5s 触发报警

## 7. 综合建议

### 推荐技术栈清单

| 层级 | 选型方案 |
| :--- | :--- |
| **前端框架** | React 18 + TypeScript + Taro 4 |
| **UI 组件库** | HeroUI Pro（Web）/ Taro 原生组件 + HeroUI Token（小程序） |
| **样式方案** | Tailwind CSS（双端共享） |
| **状态管理** | Zustand / Redux Toolkit |
| **后端框架** | Python FastAPI |
| **主数据库** | PostgreSQL（阿里云 RDS） |
| **知识图谱库** | Neo4j |
| **本地存储** | SQLite（小程序）/ IndexedDB + Dexie.js（Web） |
| **缓存** | Redis |
| **数据处理** | CRDT + 乐观锁 |
| **部署** | Docker Compose + 阿里云 ECS + RDS + OSS/CDN |
| **CI/CD** | GitHub Actions + miniprogram-ci |
| **监控** | Prometheus + Grafana |

### MVP 最小技术栈

| 组件 | MVP 方案 | 理由 |
| :--- | :--- | :--- |
| 前端 | React + Taro + Tailwind CSS | 不计 UI 库，快速搭建 MVP |
| 后端 | 单一 FastAPI（模块化而非微服务） | 避免过早拆分 |
| 数据库 | PostgreSQL（Neo4j 暂用 JSONB + CTE 模拟） | 核心闭环跑通后再引入 |
| 缓存 | Redis | 必须，降 BKT 计算压力 |
| 部署 | Docker Compose（单机 ECS + RDS） | 最快上线路径 |

### 风险与缓解

| 风险 | 缓解 |
| :--- | :--- |
| **Taro 小程序性能**：图表/动画大数据量下可能存在性能问题 | 核心图表用原生 `<canvas>`；列表虚拟化；Taro 4 render 优化 |
| **知识图谱 CTE 模拟瓶颈** | 设 SQL 慢查询报警，瓶颈发现即切 Neo4j |
| **离线同步冲突** | 严格 CRDT 计数器设计；单元测试 + 压力测试覆盖 |
| **HeroUI Pro License 成本** | 评估月费/Royalty 模式，与节省的 UI 开发工时对比 ROI。V 版：MVP 先用 Tailwind 手搓核心页面，再逐步引入 HeroUI |
