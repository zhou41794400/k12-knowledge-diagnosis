# 项目管理计划

## 管理方式

- 以阶段推进为主，不并行展开过多主线。
- 以 Obsidian 为单一过程文档中枢。
- 以 [[版本日志]] 记录关键决策、变更和阶段推进。

## 阶段控制

1. 启动：冻结目标、角色、约束
2. 规划：固定范围、知识体系、数据模型、阶段路线
3. 执行：落实知识库、服务、分析链路和视图
4. 监控：跟踪绩效、偏差、变更请求和问题修正
5. 收尾：沉淀经验教训与可复用资产

## 质量控制

- 文档与实现同步更新
- 重要输出必须可追溯
- 每阶段都要有可验收产物
- 低置信度分析必须进入人工复核

## 配置与版本管理

- Obsidian 文档作为过程主档
- GitHub 仓库作为代码与版本发布主档
- 重大范围和规则变化需双重留痕
- 插件使用方式与文档协作方式见 [[Obsidian工作流规范]]

## 沟通机制

- 当前以 Codex 主控推进
- 每次阶段推进都更新项目首页、路线图、版本日志
