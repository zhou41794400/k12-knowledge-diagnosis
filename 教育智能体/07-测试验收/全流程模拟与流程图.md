# 全流程模拟与流程图

## 模拟结论

2026-07-11 使用临时 Vault 执行 13 条端到端流程，正式学生日志未被修改。结果为 13 条通过、0 条失败。

| 流程 | 结果 | 核心断言 |
| --- | --- | --- |
| 手动录题正确 | 通过 | 生成 `rule-v2` 证据和掌握状态 |
| 手动录题错误 | 通过 | 负向证据累计一次 |
| 答案缺失 | 通过 | 只写题目和审计，不写证据与掌握度 |

## 一、业务主流程

```mermaid
flowchart TD
    A["家长获得监护人授权"] --> B["录入题目"]
    B --> C{"录入方式"}
    C -->|手动| D["填写题干、答案、学生作答"]
    C -->|照片| E["本地 Tesseract OCR"]
    E --> F["OCR 文本待人工确认"]
    F -->|修正并确认| D
    F -->|放弃| X1["仅保留导入审计"]
    D --> G["校验学科、年级、已发布知识点"]
    G --> H{"映射结果"}
    H -->|唯一命中| I{"答案能否判断"}
    H -->|无匹配| R["人工复核队列"]
    H -->|多候选歧义| R
    I -->|能| J["生成证据并更新规则掌握度"]
    I -->|不能| R
    J --> K["SQLite 保存当前状态"]
    R --> K2["SQLite 保存题目和审计"]
    K --> L["JSONL 追加审计"]
    K2 --> L
    L --> M["生成家长端、学生端、题目详情"]
    M --> N["家长查看短板与复核项"]
    M --> O["学生低频查看复盘与建议"]
```

## 本次发现并修复

1. 待判断题原先会增加证据计数，现已改为只写题目和审计。
2. 模拟脚本原先不能从 `scripts/` 直接导入项目包，现已修复入口路径。
3. SQLite 与 JSONL 原先逐条非原子双写，现改为 SQLite 事务加可重试 outbox。
4. 报告原先漏算未匹配和 OCR 待确认项，现改为读取独立复核任务。
